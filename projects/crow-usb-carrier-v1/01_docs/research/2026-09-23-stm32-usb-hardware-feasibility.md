# STM32H743 + USB3300 hardware feasibility, read-only — 2026-09-23

**Assessment: conditional hardware yes; complete USB audio design no.** The JLC-stocked STM32H743VIT6 (C114409, 3520) plus USB3300-EZK-TR (C108383, 23018) provide a credible *bare-IC* route for eight simultaneous 48 kHz/24-bit capture channels. Each exceeds the five-board plus 150-unit per-code target of **155**. The package exposes the required USB HS ULPI and a separate SAI TDM input pin group, and high-speed USB packet capacity exceeds the audio payload. This is sufficient to justify a detailed architecture candidate, not part adoption, a complete pin assignment, timing proof, working image, host interoperability, or JLC allocation. Raw JLC responses, UTC timestamps and SHA-256 hashes are retained in `/tmp/crow-active-sourcing-20260922/alternates/stm32_search.jsonl` and `ulpi_search.jsonl` with corresponding raw JSON. No firmware source was authored or built.

| Requirement | Concrete evidence and proposed allocation | Remaining proof |
|---|---|
| USB HS device | [ST STM32H743VI datasheet](https://www.st.com/resource/en/datasheet/stm32h743vi.pdf) §3.40: OTG_HS1 provides 480-Mbit/s high-speed with external ULPI PHY, 4-Kbyte combined endpoint FIFO and nine bidirectional endpoints. [Microchip USB3300 datasheet](https://ww1.microchip.com/downloads/aemDocuments/documents/UNG/ProductDocuments/DataSheets/USB3300-Data-Sheet-DS00001783.pdf): USB HS ULPI PHY, 3.3-V supply with internal 1.8-V regulators. | USB signal integrity, reset/VBUS sensing, powered-state isolation, FIFO/endpoint configuration, and high-speed enumeration on the actual PCB. |
| **LQFP100 pin availability** | ST pinout/table lists USB ULPI clock PA5, D0 PA3, D1 PB0, D2 PB1, D3 PB10, D4 PB11, D5 PB12, D6 PB13, D7 PB5, STP PC0, DIR PC2, NXT PC3. All appear on LQFP100. PC2_C/PC3_C package pads require closing the documented SYSCFG analog switches for the PC2/PC3 alternate functions. Absent PH4/PI11 are *alternate* DIR/NXT routes, not mandatory. | Confirm reset-time switch setup before ULPI use and complete electrical/pin audit; reserve all twelve ULPI signals and PHY RESET/VBUS. No verified netlist or CubeMX pinout was produced. |
| Eight-channel TDM capture | The [ST STM32H743 reference manual](https://www.st.com/resource/en/reference_manual/dm00314099-stm32h742-stm32h743-753-and-stm32h750-value-line-advanced-arm-based-32-bit-mcus-stmicroelectronics.pdf) documents SAI 24/32-bit samples and programmable TDM frame/slot count (up to 16 slots). A conflict-free *candidate* SAI1 group is PE2 MCLK_A, PE4 FS_A, PE5 SCK_A, PE6 SD_A; these are present on LQFP100 and do not overlap the ULPI pins above. Eight 32-bit slots ×48 kHz means 12.288-MHz BCLK, one 24.576-MHz MCLK and a 1.536-Mbyte/s 32-bit receive-DMA stream. The retained CS5308P source presently has **one** eight-channel ADC data output, so one SAI data input is the relevant current path; any proposed pair of quad ADCs needs its own clock/slot/wire proof. | SAI master frame polarity, CS5308P launch/capture edge and slot placement per Cirrus DS1314F2, DMA/cache/bus placement and long-run clock drift. SAI peripheral capability alone is not a tested eight-channel data path. |
| Audio clock | ST accepts 4–50-MHz external HSE input and has three PLLs; 24.576 MHz may be fed to HSE and used as the common source for SAI-derived MCLK/BCLK/FS, while the ADC receives the same audio reference. This is a *candidate* synchronized topology. PH0/PH1 oscillator pins are bonded on LQFP100. | Prove PLL divider legality/jitter, HSE bypass electrical levels, clock fanout/loading, ADC/MCLK versus BCLK edge alignment, clock startup and sample-clock-to-USB pacing. Do not assume an independent MCU oscillator is synchronized to the ADC. |
| PHY clock and rails | USB3300 requires **24.000 MHz** crystal or external reference at XI and generates 60-MHz ULPI CLKOUT; the 24.576-MHz audio clock is not its reference. The PHY takes 3.3 V and internally creates 1.8 V with proper REG_EN and bypassing; STM32H743VI takes a 3.3-V VDD domain with on-chip core regulator and VCAP capacitors. The two chips do not reuse XU316's 0.9-V core or 1.8-V USB-rail scheme. | Add and source a 24-MHz reference, verify JLC 155-unit coverage for every added SMD, check 3.3-V current/transients, proper PHY and MCU sequencing, and rerun power/back-power analysis. Existing 24.576-MHz oscillator cannot be wired directly to USB3300 XI. |
| Control/debug | PB8/PB9 provide I²C1 SCL/SDA candidates, separate from ULPI and SAI; PA13/PA14 remain for SWD. STM32H743VI has on-chip flash/RAM; a separate XU316-style boot flash is not automatically needed. | Verify ADC control arrangement: current CS5308P source uses hardware straps, while any new quad-ADC pair may need I²C. Complete reset/boot and GPIO assignment. |
| USB payload | Eight ×48,000×24 = **9.216 Mbit/s**, or **144 bytes per 125-µs HS microframe** (six samples/channel), below a 1024-byte HS isochronous packet. Even transferring all 32-bit slots is 192 bytes/microframe. This is an arithmetic link-budget screen, not USB controller throughput evidence. | UAC2 8-channel descriptors, correct sample packing, asynchronous IN/clock-domain flow control, DMA/USB buffering, Linux/Pi recognition and sustained eight-channel capture. |

**Software availability and boundary.** [TinyUSB upstream](https://github.com/hathach/tinyusb) has a UAC2 device-class implementation and audio examples. Its [STM32H7 family code](https://github.com/hathach/tinyusb/blob/master/hw/bsp/stm32h7/family.c) configures OTG HS/ULPI as device root-hub port 1; its [getting-started guide](https://github.com/hathach/tinyusb/blob/master/docs/getting_started.rst) names the STM32H743 eval board and HS port selection. Its [UAC2 speaker example configuration](https://github.com/hathach/tinyusb/blob/master/examples/device/uac2_speaker_fb/src/tusb_config.h) shows HS endpoint sizing but is stereo output, not an eight-channel capture image. [ST X-CUBE-USB-AUDIO](https://www.st.com/en/embedded-software/x-cube-usb-audio.html) targets USB Audio Class 1.0 and is likewise not a ready solution. Hardware and generic middleware therefore exist, but no verified, preexisting, board-specific eight-channel UAC2 capture firmware image was found. A future deliverable must integrate TinyUSB/USB HS, SAI RX DMA, clock-domain flow control, ADC control/reset, UAC2 descriptors, and host validation. Under Q2, researching that contract is permitted; authoring/building/releasing it is not. The selected XU316 also owes board-specific firmware, so programmability alone is **not** a reason to reject this candidate.

**Recommended next architecture decision:** qualify STM32H743VIT6 + USB3300 as a viable hardware candidate for comparison with XU316, conditional on full pin/electrical/clock review and all newly added SMD stock screens. Its two principal new hardware burdens are a separate 24-MHz PHY reference and the 3.3-V/VCAP/USB-PHY power and reset network; its principal software burden is a new, unverified eight-channel UAC2 application. This is a major redesign of the selected XU316 subsystem, so do not silently adopt it. It can be presented to the user as a concrete architecture choice once the remaining hardware blockers are bounded. External firmware work remains explicitly owed for either architecture.
