# P1 corridor contract: smallest viable successor to the straight-lane screen

**Disposition: design only; P1 remains INCOMPLETE.** The source requirements still have `geometry: null`. This note does not edit the board, checker, requirements, task graph, or a P1 dispatch. The present `p1_corridor_capacity.py` schema-1 JSON measures one rectangular `through_lane` per allocation. Its raw width is useful for rejecting a proposed neck, but a complete Crow allocation is a network of local escapes, shared trunks, turns, branches, and sometimes a non-routing boundary. A source-only correction is necessary for CHASSIS identities but cannot solve the USB/ADC topology, endpoint exclusion, or GND fill evidence gaps.

## Contract shape and migration

Add a **new** checker contract schema (do not reinterpret schema 1): a hash-bound graph under each of the four named allocations, plus `power_boundary_windows` and a separate `mechanical_boundaries` section. Keep the source YAML as the 59-net ownership denominator; derive the checker input from it and reject differences rather than maintaining two independent coverage lists. Each net has an explicit terminal set and a connected graph of segment IDs and pocket IDs. A segment has a unique ID, native copper layer, board-mm polygon (rectangles are the first supported polygon), ordered port/junction IDs, assigned nets, effective width/clearance demand, and a reservation/capacity status. A junction names the common on-board aperture and layer; a layer change requires an explicit via/transition and return-transition record. A pocket names one or more exact native `ref.pad/net` terminals, its small on-board pad-access polygon, its port, and a source-to-native alias when the source pad number differs. Multiple pads on one footprint may have separate pockets. Every listed terminal must reach the graph for its net; each branch must be measured. A segment with 9 slots is not evidence for 44 terminal accesses.

Use an explicit `kind` for each allocation component: `signal_corridor`, `power_window`, or `mechanical_boundary`. `CHASSIS` is the latter: verify the 16 native RJ45 shell pads `J1..J8.9/.10`, their local edge boundary and clearance to circuit GND and J_USB shell, without inventing a CHASSIS through-lane. The current YAML `J1.SHIELD`..`J8.SHIELD` is neither source nor native pad identity. The proposed source correction moves CHASSIS from `usb_device_pair` to the power/mechanical boundary owner. Exact-once coverage is still **59 distinct nets**: USB 4, XMOS service 13, ADC timing 14, ADC analog 18, and power/mechanical 10. Update the `crow-p1` checker profile and source YAML atomically when implementing this migration. Keep the power rails as multi-window current/return/thermal evidence, not scalar signal slots.

For `J_USB`, preserve schematic-to-native aliases from `USB4215-03-A/part.yaml`: `4/12 → A6/B6` for USB_DP, `5/13 → A7/B7` for USB_DN, and `2/7/10/15 → A4/A9/B4/B9` for VBUS_USB. Confirm each native pad's actual net; duplicate logical contacts sharing one physical land remain separate source members with an explicit many-to-one alias, not duplicated copper capacity. `J_USB.17 → SH` is native GND, separate from CHASSIS. Reject absent, ambiguous, swapped, or unbound aliases and all source/native endpoint-set drift. Retain the source endpoint owner and demand IDs so the migration can report precisely which of the 59 nets and which pad accesses remain incomplete.

## On-board geometry and capacity evidence

A normal pocket must contain its target pad's on-board copper access region and connect to its named port; it need not contain the entire footprint body. The body, courtyard/process envelope, every **other** pad on that footprint, and foreign bodies/pads remain obstacles unless an explicit, native-rule-checked exception applies. The target pad is exempt only within its own access polygon. A source endpoint reference must never cause whole-footprint exclusion. Check pocket-to-segment and segment-to-segment apertures after clearance expansion; touching bboxes or a zero-width corner do not establish access. Do not infer connectivity from overlapping reservations on different layers.

The USB4215 is a named edge-connector exception to whole-body-on-board containment. Bind the exact native footprint ID/transform, target pad polygon, Edge.Cuts polygon, intended board-edge segment, and manufacturer mouth datum in one board-hash receipt. Clip the copper access pocket to the physical board, then verify that the target pad is on board, the mouth-to-edge offset and overhang match the approved drawing/tolerance, and off-board body/courtyard is confined to that explicitly reviewed connector envelope. All non-target pads and shell lands still constrain access. Reject a generic off-board pocket or a missing/misaligned datum. This addresses the observed J_USB bbox y=19.470 while the board starts at y=20 without weakening ordinary endpoint checks. RJ45 shell boundaries need their own edge/keepout and separation checks.

For each segment and junction, report the **native-layer, rule-expanded** free apertures and simultaneous assigned-net demand. The demand must account for each net's effective trace width and clearance, differential pair width/gap and bend envelope where applicable, and reservations shared by other allocations. At a branch, validate each terminal path and aggregate demand on common edges; at a turn, validate the joint aperture, not just the adjacent rectangles independently. A conservative upper bound below demand is `FAIL`; a free raw bbox is only `INCOMPLETE`. If the checker cannot establish a simultaneous disjoint-channel witness under effective rules, report `INCOMPLETE`, never `PASS`. Inventory effective `.kicad_pro`/`.kicad_dru` rules and native rule-area polygons (including same-layer TMUX areas), with source and board hashes. Report actual failing cross-section, involved native obstacles, demanded nets, and uncovered terminal/edge IDs. Keep DRC and later routing evidence separate from this P1 reservation screen.

The In1.Cu GND zone is a **reference** for F.Cu signal lanes, not an obstacle merely because its bbox spans the board. Require a saved, filled native board whose post-save SHA is the evaluated board SHA. For each full signal-path envelope, compare the native filled GND polygons (correct layer and net) against the projected path plus prescribed return margin; subtract holes, non-GND clearances, and necks, and check return continuity and transitions. Sparse point samples or an in-memory unsaved refill do not prove continuity. If the zone is unfilled, the polygon is interrupted, or the reference recipe is absent, return `INCOMPLETE`; a demonstrated return break fails the proposed path. Same-layer pours remain copper obstacles/constraints according to net and effective rules. Hash-bind the zone/return receipt and DRC/rule sidecars to the same saved board.

## Fail-closed implementation gates

1. Keep schema-1 fixtures and behavior as diagnostic history. Add schema-2 fixtures for two-segment turns, shared-edge contention, a branched ADC net whose remote pad is disconnected, and overlapping but layer-disconnected segments. A missing segment, pocket, alias, terminal, or transition must leave the allocation incomplete; an undersized proven neck must fail even when another allocation or proof is incomplete. Preserve all allocation-level results rather than masking `FAIL` with a top-level `INCOMPLETE`.
2. Test exact source/native pad-net parity and 59-net exact-once coverage, including the USB A/B alias and all 16 RJ45 CHASSIS pads. Verify same-footprint non-target pads block escapes; separate ADC pad pockets can share one package without exempting its other pads. Exercise off-board USB mouth registration and reject an arbitrary off-board ordinary endpoint.
3. Test saved filled GND containment with a deliberate void/neck, wrong-net or wrong-layer zone, stale post-fill board hash, and TMUX rule-area overlap. Never convert a raw-slot result, unfilled zone, point-sampled plane, or missing effective rules into P1 acceptance. A board/contract/sidecar hash mismatch or zero denominator is a hard invalid/incomplete receipt.

The immediate source repair is the CHASSIS endpoint/owner correction. It is independently valuable, but the graph contract and native evidence above are still required before the four allocations can be assessed on one frozen P1 board. The checker should continue emitting `routing_realized=false` and `p1_accepted=false`; ADR 0011 review and connector FULL remain separate gates.
