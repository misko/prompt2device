## Exact pin owners and current seam

`projects/crow-usb-carrier-v1/02_parts/USB4105-GF-A-120/part.yaml` declares all 17 logical contacts with `pin_aliases`: schematic `1..17` maps respectively to physical `A1,A4,A5,A6,A7,A8,A9,A12,B1,B4,B5,B6,B7,B8,B9,B12,SH`. Circuit JSON `source_component_560` J_USB carries numeric source ports 1..17 and three extra internally connected shell ports. Its source nets are correct: A6/B6 D+, A7/B7 D−, CC1/CC2 separate, VBUS/GND group, SBU no-connect, SH GND. The PCB-disabled circuit JSON has no PCB pad identity. In `skills/kicad-pcb/scripts/circuit_json_to_kicad_sch.py`, `load_model()` lines ~365–435 resolves `pad_name()` from authoritative PCB hints or numeric `pin_number`; the numeric fallback is why the native symbol has `1..17`. The three shell extras resolve to parent `17` via `internal_pad_aliases`. Later `build_symbol()`/`lib_symbol_geo()` and `emit_component()`/`_emit_layout_component()` use the model pad as the KiCad symbol pin number and key for placement/labels. Thus normalize in `load_model` before symbol synthesis; do not post-edit the generated sheet or change source TSX/CJ.

`generate_board_generic.py::resolve_pad_aliases()` already maps the same dossier with `pin_map_check.load_parts()` and `alias_map()` while preserving the netlist; the board's physical pads are already A/B/SH. Keep its compatibility with either old numeric or newly physical schematic netlist. It has an ambiguity check when an incoming token could denote two different pads, and checks collisions/fused aliases. For this board the only **selected** `pin_aliases` dossiers are USB4105-GF-A-120/J_USB (17 renames) and DMP6023LFG-13/Q_IN (three fused manufacturer drain identities 6,7,8 all `schematic: 5`, `footprint: 5`). Q_IN already emits physical 5; mapping must be idempotent and must not materialize phantom 6/7/8 symbol pins. The current P-PINMAP gate passes, but it only checks dossier-to-artifact reachability; it does not make the native sheet's pin numbers equal the board's.

## Bounded implementation

1. Add a dossier alias loader to the native converter, preferably reusing `pin_map_check.load_parts()`/`alias_map()` (already used by the board generator) or factoring their parser into a small shared module. Resolve by the component's exact MPN/supplier code, as `load_part_overrides()` and `load_part_ties()` currently do. Fail on an active ambiguous identifier, malformed active alias, or dossier footprint differing from `resolve_fpid()`. Preserve non-aliased legacy behavior. Avoid a second permissive YAML/regex parser with different alias semantics; PyYAML/pcbnew are already pipeline dependencies. If importing `pin_map_check` into standalone schematic conversion would force pcbnew in an environment that lacks it, factor only its pure `load_parts`/`alias_map` helpers into a pcbnew-free shared module or use lazy import with explicit error.
2. In `load_model`, establish per-component `schematic -> physical` map before looping its source ports. Keep source-port ID, source function, and canonical net unchanged. Resolve the raw pin exactly as now (PCB hint first, otherwise numeric or internally connected parent); normalize numeric identities through the exact dossier map; accept an already-physical pad idempotently; reject ambiguous or unknown identities on aliased parts. Build `portinfo[*].pad`, `pins`, and extra tie-pad de-duplication from the normalized pad. If two ports collapse to a physical pad, require matching non-null nets and documented `fused:true`; do not use current `None`/connected winner behavior to conceal a conflict on a mapped pad. This makes both layout and grid emitters inherit the same physical numbers; the three shell aliases become SH and the `no_connect` flags stay on A8/B8.
3. Datasheet field: the board loads the footprint library's populated Datasheet property, but both schematic emitters omit it. The clean generic parity contract is for both generators to use the exact dossier `datasheet.url` for the selected component's KiCad Datasheet field. Add a `datasheet` value to the converter's component model from the matched dossier and emit a hidden `(property "Datasheet" ...)` in **both** `emit_component()` and `_emit_layout_component()`. Also make the board loader set its Datasheet field from that same dossier URL (or, more narrowly, make converter emit only when the selected footprint's existing Datasheet field is nonempty and matches the dossier URL). Emitting every dossier URL on the schematic alone would create fresh mismatches against other library footprints whose Datasheet is blank. The shared-source two-generator option is more durable; it is metadata-only. Confirm the exact U_SPOKE URL remains byte-for-byte equal on both.
4. Focused verification: unit fixture with J_USB numeric ports 1..17 plus internal shell duplicates, exact dossier and both layout/grid model paths; assert physical A/B/SH symbols and portinfo, unchanged per-contact nets, A8/B8 NC, duplicate SH collapse, and Q_IN fused/identity behavior. Add a negative alias collision/net conflict fixture. Then regenerate schematic in an isolated trial, export netlist, build board from it, and run KiCad DRC `--schematic-parity`; require zero findings (not just P-PINMAP). Compare canonical per-ref/per-pad net map before/after using dossier translation; verify 45 prior warnings disappear without new ones. Keep unrelated physical DRC violations/unconnected count separate.

KiCad's symbol pin **number** is the native footprint-pad identity used by schematic parity. Symbol pin alternate names/functions and PCB net-tie groups do not express a numbering alias for this comparison. The converter is therefore the right owner for the pin bridge, using the existing exact dossier; editing accepted CJ, assigning numeric names to physical footprint pads, or waiving the parity check would lose the source/physical identity contract.
