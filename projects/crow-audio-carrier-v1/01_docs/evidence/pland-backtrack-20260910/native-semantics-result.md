## Semantic adjudication

1. **Strings and precedence.** `LIBEVAL::VALUE::EqualTo` performs case-insensitive string equality. A RHS string containing `*` or `?` uses wildcard matching; square brackets are literal, not Python fnmatch character classes. The archived native `case_insensitive` run has one target width finding for uppercase REMOTE_HIGH_T; `bracket_literal` has none for remote_high_[T]. Their rejected-kernel answers disagree in opposite directions. The Lemon grammar declares AND below OR: `false && true || true` groups as `false && (true || true)`, hence false. The archived mixed condition has no target finding, consistent with that grammar. Rejecting unparenthesized mixtures is a permissible narrower admission, but implementing ordinary Python precedence or the WIP's left-to-right folding is not. Source: archived libeval compiler and grammar, corroborated by [KiCad 10.0.4 grammar](https://raw.githubusercontent.com/KiCad/kicad-source-mirror/10.0.4/common/libeval_compiler/grammar.lemon).

2. **Area membership.** `insideArea` registers the same implementation as `intersectsArea`. For Track/Pad objects it intersects the item's native effective shape on the selected layer with a native clone of the area outline, after ClearArcs and Deflate(actual GetDRCEpsilon(), ALLOW_ACUTE_CORNERS, ARC_LOW_DEF). This is not center containment or complete-track containment. Exact touch and 1-IU intrusion give no match at the recorded 500-IU epsilon; 2um intrusion matches. The archived area-relaxation script is a SyntaxError with rc1 and no child native result, so its hypothesized false acceptance was not previously measured. This reassessment independently completed that control: 0.2mm track, earlier 0.4mm width floor, later 0.2mm area relaxation with 1-IU intrusion produces exactly one native target width finding under the earlier highbase rule, no opens. The WIP's positive-area intersection is therefore not a safe replacement. Missing named area, unsupported area shape or uncertain deflation must block admission, never silently make a relaxation true or false.

3. **Local PAD/FP precedence.** PAD's optional local value is selected first; explicit zero is present and masks the footprint value. Only absent PAD local falls back to FP local. For a copper pair take the largest selected local override. If that value is nonzero, native clearance returns it clamped to board minimum before custom rules. If all selected values are zero/absent, it falls through. Ten archived native controls prove nonzero PAD and FP versus competing custom rules, PAD masking FP, zero masking FP, zero then custom, zero without custom, and below-board cases. The custom0.05/gap0.075 control passes despite board0.1; nonzero local0.05 at the same gap fails with board0.1; explicit PAD0 masking FP0.3 falls through to the custom0.05 and passes. `max(board, all rules, all locals)` is wrong, as is treating PAD0 as absence. The [10.0.4 engine](https://raw.githubusercontent.com/KiCad/kicad-source-mirror/10.0.4/pcbnew/drc/drc_engine.cpp) returns explicit custom constraints before its later implicit-clearance clamp.

4. **Width versus board minimum.** Board minimum width is an implicit initial constraint; explicit matching width minima overwrite it. The provider compares integer track width to resolved min/max, not to a separately forced board floor. Fresh native controls with actual0.075mm return no violations/opens for explicit min0.05 and exactly one target width violation/no opens for explicit min0.1. Do not clamp an explicit width floor upward to board minimum, and do not invent declared P-LAND floors from board/netclass defaults. Netclass track-width preferences are not declarations that every pad must be graded.

5. **Pair condition ordering.** KiCad evaluates a pair condition for (A,B) and, when necessary, (B,A); single-track width calls use B=null and do not swap. This is directly visible in [DRC_RULE_CONDITION::EvaluateFor](https://raw.githubusercontent.com/KiCad/kicad-source-mirror/10.0.4/pcbnew/drc/drc_rule_condition.cpp), additionally fetched and SHA bound here. Implement per-rule matching over both orderings, then ordered rule selection. Do not resolve two independently ordered rule lists and take their maximum.

## Minimum kernel contract, seven groups

**1 — Closed syntax and condition language.** Parse the entire file into a typed, source-located AST; require one version1 declaration and valid rule names. Admit conditionless rules, one nonempty string condition, and one or more individually valid constraints; reject duplicate attributes/constraint kinds, malformed strings, unexpected tokens, trailing material and empty attribute bodies. Support ASCII string literals, A/B.NetName, A/B.NetClass, A/B.Type, equality/inequality against RHS literals, `!`, parentheses, `&&`, `||`, and literal-name insideArea/intersectsArea. Preserve KiCad precedence and case semantics; use only `*`/`?` wildcards, or explicitly reject those patterns until their native controls pass. Reject reversed operands, property-to-property comparison, numeric arithmetic, Layer property expressions, other functions/properties and escaped/Unicode literals until independently supported. An unsupported leaf must reject even inside an invariant-false branch. Width AST admission rejects every B dependency before folding. Current corpus needs NetClass, NetName, Type, AND/OR, parentheses and literal areas; it has no rule-layer attributes or Layer property expressions. Thus these named restrictions do not exclude current corpus demand. Structurally validate CRC's diff_pair_gap min/opt and inventory it as a downstream differential-pair obligation; it cannot be silently dropped or treated as pad-launch clearance. Reject all other irrelevant constraint kinds initially, including malformed `(constraint via_diameter malformed)`, even in a rule with no supported constraint. Independent regression: malformed irrelevant-rule reproducer, each unsupported leaf under false branch, uppercase/literal brackets, both mixed precedence examples, != and negation, missing/duplicate attribute, rule-layer/property rejection, CRC diff_pair_gap inventory.

**2 — Complete resolved classes.** Load the exact board and same-stem project explicitly through the qualified native API. Check the complete serialized class records, native resolved effective class, constituent classes, numeric clearance and net assignment for every pad and candidate net. Never infer assignment by first regex match or truncate a composite name. NetClass-versus-literal matches any constituent OR the complete effective name, case-insensitively with supported wildcard semantics; != negates membership and full-name match. Property-to-property NetClass equality uses native netclass object equality and is deliberately rejected by this initial grammar. Current/native fixture classes may resolve differently depending on completeness; retain all original class definitions and expected assignment receipts. Regression: exact complete-class base and hostile fixtures, two constituent names and full name with ==/!=, default inheritance, two net patterns assigning one net, project reload with a changed assignment and stale/missing project rejection. All classes must have readable effective clearances; an unreadable class is not floorless.

**3 — Ordered width/clearance constraints.** Admit finite, nonnegative constant quantities in mm (and mil only after exact conversion tests), integer IU conversion, track_width min and clearance min. Reject negative/nonfinite quantities, unsupported min/max/opt combinations on these two constraints and zero-width candidates. For the supported min-only list, latest matching rule of that kind supplies the minimum; otherwise native implicit width/clearance applies to candidate validation. Clearance conditions resolve on the actual fixed-width Track and each actual obstacle Pad in both orderings. Source Pad.Type/area truth cannot stand in for Track.Type/area truth. Cache only invariant class/net/type/layer facts; all area truth is evaluated on that exact candidate width and segment. Width declared eligibility and candidate validation are separate: a pad with any potentially applicable declared Track-width rule is graded or explicitly blocked; only a proved absence of applicable declared floors becomes no_floor. Regression: stricter and looser later rules, conditions distinguishing Pad/Track, A/B reversal, remote high-clearance pad, matching board-below custom clearance, and fresh width-below-board pair above. Required native baseline matrix remains 18 base/18 hostile specified tracks; it proves only those tracks.

**4 — Local precedence.** Support absent/zero/nonzero nonnegative PAD and FP optionals for copper Track–Pad pairs exactly as adjudicated. **5 — Native geometry.** Use pcbnew effective shapes at integer IU for the selected layer for source admission, candidate capsules, obstacle collision/distance and area deflation/intersection. **6 — Layers, holes and guards.** Public pad assessment computes eligible launch layers itself: pad copper layer mask intersected with board enabled copper layers, in native UI order.
