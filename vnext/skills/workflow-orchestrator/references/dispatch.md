# Dispatch a bounded task

Use the [task interface](task-interface.md) and the active domain contract.

1. Reopen required accepted inputs and applicability. Check the user's scope
   and next checkpoint before starting downstream work. Apply the
   [milestone dispatch gate](recover.md#milestone-plateau-despite-local-success)
   before any worker launch, including review, research and escalation. A note,
   new allowance or task packet does not replace a permitted dispatch. Check prior attempts on
   the same decision against the [stagnation checkpoint](recover.md#stagnation-checkpoint)
   before assigning another author, including prerequisite research.
   Resolve the domain graph's applicability and execution binding: a catalog
   node or definition-only contract is not a runnable adapter. Name the missing
   implementation when absent; component tests cannot promote the whole stage.
   Use the current dated authority for the task while preserving older scope
   snapshots as historical receipt inputs, not competing live instructions.
2. Select by milestone impact, not convenient task availability. In the existing
   journal state which unresolved condition for the next deliverable this task
   will close and why it is the highest-value available action. Prefer a
   topology/strategy-changing uncertainty or a complete end-to-end function
   over optional local refinement. The domain defines which details are critical.
   If a higher-impact action needs external authority, surface it and choose
   genuinely independent useful work; do not imply that work resolves the hold.
   Group low-risk detail with shared inputs into a coherent deliverable.
   Name its verifier and writer. Declare the exact
   allowed writes, positive deadline and progress signal.
3. Build a context packet from the active stage contract, relevant procedures,
   input/evidence references, interface constraints and current findings.
   Keep required safety/acceptance rules; exclude unrelated future-stage work.
4. Use deterministic tools for mechanical loops, bounded authoring for changes
   and judgment for unresolved diagnosis or independent review. State why an
   escalation is needed; use configured provider/model preferences.
5. Execute through the adapter's existing bounded path. Record each attempt,
   including setup failures. Do not infer successful work from a dispatched job.
6. Reopen outputs with the named verifier. Acceptance is a separate operation
   performed only by the authorized consumer.

Before a multi-task run, read its authorized execution policy from the adapter's
existing records: worker/reviewer roles, expert-escalation allowance, total
budget and user checkpoints. Reserve both expert and independent-review capacity
inside that total when escalation is authorized. A worker timebox returns control
to the coordinator; continue in scope without asking the user again when the
policy permits it. Neither unused time nor a new worker renews attempt limits.

Use measurable elapsed-time deadlines unless an actual active-time meter is
available. Include tool/wait latency and leave time for checkpointing; a prose
timebox is not automatic cancellation. Check the clock before dispatch and
before further work near the limit; stop or interrupt at the boundary and record
any overrun. Refresh the adapter's existing live status at dispatch, review and
recovery transitions, preserving the exact pre-mutation dispatch inputs.

Do not preload entire histories, tool implementations or every component
dossier. Load evidence relevant to the task, and expand when a named unresolved
question requires it. Record loaded files and size for the pilot; byte/word
counts are estimates of instruction load, not exact model token usage.

Give component tasks explicit shared interfaces and one integration owner.
Parallelize only isolated writes or read-only work. An integration failure
returns to its causal owner; independent child success cannot override it.

A timeout/error preserves prior accepted evidence and goes to
[recovery](recover.md). A requested checkpoint goes to [resume](resume.md).
